# Marketplace Stage 1 — Auth Service v0.2

This increment adds controlled database migrations, password recovery, protected user access, authentication dependencies, and async integration tests.

## Included endpoints

```text
POST /api/v1/auth/register
POST /api/v1/auth/verify-email
POST /api/v1/auth/login
POST /api/v1/auth/refresh
POST /api/v1/auth/logout
POST /api/v1/auth/forgot-password
POST /api/v1/auth/reset-password
GET  /api/v1/users/me
GET  /health
```

## Run with Docker

```powershell
Copy-Item .env.example .env
docker compose up --build
```

The container runs `alembic upgrade head` before starting FastAPI.

When running inside Docker, the app must connect to service DNS names (not `localhost`):

```env
DATABASE_URL=postgresql+asyncpg://marketplace:marketplace@postgres:5432/marketplace_auth
REDIS_URL=redis://redis:6379/0
```

- Swagger: http://localhost:8001/docs
- Health: http://localhost:8001/health

## Run locally

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
Copy-Item .env.example .env
```

For local execution outside Docker, set `.env` for how dependencies are running:

If Postgres/Redis run on your host directly:

```env
DATABASE_URL=postgresql+asyncpg://marketplace:marketplace@localhost:5432/marketplace_auth
REDIS_URL=redis://localhost:6379/0
```

If you reuse Postgres/Redis from this compose stack (published ports):

```env
DATABASE_URL=postgresql+asyncpg://marketplace:marketplace@localhost:5433/marketplace_auth
REDIS_URL=redis://localhost:6380/0
```

Then run:

```powershell
alembic upgrade head
uvicorn app.main:app --reload
```

## Alembic commands

```powershell
alembic current
alembic history
alembic revision --autogenerate -m "describe schema change"
alembic upgrade head
alembic downgrade -1
```

Always review autogenerated migrations before applying them.

## Run tests

```powershell
pytest -q
```

The integration suite uses an isolated SQLite database and tests:

- Registration, verification, and login
- Protected `GET /users/me`
- Missing authentication
- Refresh-token rotation and replay rejection
- Forgot/reset password
- Old password rejection
- Refresh-token revocation after password reset
- Password-reset token single use
- Unknown-email enumeration protection

## Development-token behavior

Verification and reset tokens are included in API responses only when `APP_ENV` is `development` or `test`. In production, publish a notification event and send the token through an email provider.
